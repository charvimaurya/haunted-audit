# Haunted Audit Kiro Integration — Design

**Spec version:** 1.0  
**Stack:** Python 3.11 · Pydantic v2 · `mcp` SDK (stdio) · Playwright · axe-core (Node)  
**Existing codebase used:** `agent/keyboard_agent/` (models, checker, runner, tools), `agent/api/main.py`, `requirements.txt`

## 2. Dependencies

Add to `requirements.txt`:
```
mcp>=1.0          # Model Context Protocol Python SDK (stdio server)
axe-playwright-python>=0.2  # OR call axe-core via Node subprocess (see §4)
```

`axe-core` ships as an npm package. Two integration strategies are possible:

| Strategy | Pros | Cons |
|---|---|---|
| **A: Node subprocess** (selected) | No Python axe wrapper to maintain; always latest axe-core; consistent with `axe-on-save` hook | Requires Node ≥ 18 in PATH |
| B: `axe-playwright-python` | Pure Python | Less maintained; may lag behind axe-core releases |

**Decision: Strategy A.** `scanner.py` writes a small inline Node script to a temp file, runs it with `node`, captures stdout JSON. The same pattern is already in use in `.kiro/scripts/axe-on-save.mjs`. Node version is checked at startup; if absent, `scan_url` and `scan_file` return `SCANNER_UNAVAILABLE`.

## 3. MCP Server Entry Point (`mcp_server/server.py`)

```python
# Conceptual — not final implementation
from mcp.server.stdio import stdio_server
from mcp import Server, tool

server = Server("haunted-audit")

@server.tool()
async def scan_url(url: str, tags: list[str] = DEFAULT_TAGS) -> dict: ...

@server.tool()
async def scan_file(path: str) -> dict: ...

@server.tool()
async def run_journey(
    journey_id: str, variant: str, mode: str = "scripted",
    max_steps: int = 25, timeout_seconds: float = 90,
) -> dict: ...

@server.tool()
async def get_run(run_id: str) -> dict: ...

@server.tool()
async def propose_fix(run_id: str) -> dict: ...

@server.tool()
async def verify_fix(run_id: str, patch: str) -> dict: ...

@server.tool()
async def list_regression_tests() -> dict: ...

if __name__ == "__main__":
    import asyncio
    asyncio.run(stdio_server(server))
```

All tool functions are `async`. They call sync helpers via `asyncio.to_thread` where Playwright or filesystem I/O is needed. No tool raises an uncaught exception; all errors are caught and returned as the structured error object.

## 4. Schemas (`mcp_server/schemas.py`)

Every tool input and output is a Pydantic v2 `BaseModel`. The schemas are the single source of truth; JSON Schema for the MCP `initialize` response is generated by `model_json_schema()`.

```python
# Abbreviated — see design for full field list
class ScanUrlInput(BaseModel):
    url: str
    tags: list[str] = DEFAULT_AXE_TAGS

class AxeViolation(BaseModel):
    rule_id: str
    wcag: str           # derived from WCAG_MAP (same map as axe-on-save.mjs)
    impact: Literal["critical","serious","moderate","minor"]
    selector: str
    html: str           # ≤200 chars
    failure: str
    help_url: str

class ScanResult(BaseModel):
    url: str
    scanned_at: str     # ISO-8601
    violations: list[AxeViolation]
    passes: int
    violation_count: int
    # scan_file adds:
    route: str | None = None
    file: str | None = None

class RunJourneyInput(BaseModel):
    journey_id: Literal["send-payment"]
    variant: Literal["broken", "fixed"]
    mode: Literal["scripted", "llm"] = "scripted"
    max_steps: int = Field(default=25, ge=1, le=80)
    timeout_seconds: float = Field(default=90, ge=0, le=300)

class RunJourneyOutput(BaseModel):
    run_id: str
    status: Literal["running"]
    journey_id: str
    variant: str
    mode: str           # = agent_mode for product-rules compliance

class GetRunOutput(BaseModel):
    run_id: str
    status: Literal["running", "complete", "error"]
    verdict: Literal["PASSED", "BLOCKED"] | None
    reason_code: str | None
    agent_mode: Literal["scripted", "llm"]
    step_count: int
    blocked_element: BlockedElementSummary | None
    latency_ms: float
    cost_usd: float
    error: str | None

class BlockedElementSummary(BaseModel):
    selector: str | None
    tag: str | None
    accessible_name: str | None
    bounding_box: BoundingBoxOut | None

class ProposeFixOutput(BaseModel):
    run_id: str
    verdict: Literal["BLOCKED"]
    reason_code: str
    blocked_element: BlockedElementSummary
    diff: FixDiff
    warning: Literal[
        "This diff has not been applied. Human approval required."
    ] = "This diff has not been applied. Human approval required."

class FixDiff(BaseModel):
    file: str
    before: str
    after: str
    wcag: str
    rationale: str

class VerifyFixOutput(BaseModel):
    original_run_id: str
    verify_run_id: str
    patched_file: str
    verdict: Literal["PASSED", "BLOCKED"]
    reason_code: str | None
    agent_mode: str
    step_count: int
    message: str

class RegressionTestEntry(BaseModel):
    name: str
    path: str
    journey_id: str
    variant: str
    last_result: Literal["PASSED", "BLOCKED"] | None
    last_run_at: str | None

class ListRegressionTestsOutput(BaseModel):
    tests: list[RegressionTestEntry]
    count: int

class ToolError(BaseModel):
    error: ErrorDetail

class ErrorDetail(BaseModel):
    code: str   # SCREAMING_SNAKE_CASE
    message: str
    status: int | None = None   # HTTP status if from backend
```

`ToolError` is returned (not raised) for all error conditions. Tool functions return `ScanResult | ToolError`, `GetRunOutput | ToolError`, etc. The MCP framework serialises whichever is returned.

## 5. Scanner (`mcp_server/scanner.py`)

```
scan_url(url, tags) → ScanResult | ToolError
  │
  ├── check Node ≥ 18 available                   → SCANNER_UNAVAILABLE if not
  ├── write inline axe script to tmp file
  ├── subprocess: node <script> <url> <tags_json>  → stdout: JSON axe results
  ├── parse stdout into list[AxeViolation]
  │     ├── map rule_id → WCAG criterion (WCAG_MAP dict, same as axe-on-save.mjs)
  │     └── sort by impact (critical > serious > moderate > minor)
  └── return ScanResult
```

The inline Node script (written at runtime, deleted after use):
```javascript
import { chromium } from 'playwright';
import AxeBuilder from '@axe-core/playwright';
const [,, url, tagsJson] = process.argv;
const tags = JSON.parse(tagsJson);
const browser = await chromium.launch({ headless: true });
const page = await browser.newPage({ viewport: { width: 1280, height: 800 } });
await page.goto(url, { waitUntil: 'networkidle', timeout: 15000 });
await page.waitForTimeout(600);
const results = await new AxeBuilder({ page }).withTags(tags).analyze();
await browser.close();
console.log(JSON.stringify(results));
```

`@axe-core/playwright` and `playwright` must be installed in `dashboard/node_modules/` (already done by TASK-20 from the frontend spec, or by `npm install --prefix dashboard @playwright/test @axe-core/playwright`). `scanner.py` resolves the Node binary from PATH and the `node_modules` from `HAUNTED_AUDIT_DASHBOARD_DIR` env var (default: `dashboard/`).

**Rate limiting:** A module-level `asyncio.Lock` prevents concurrent scans. Second caller gets `SCAN_IN_PROGRESS`.

## 6. Journey Client (`mcp_server/journey.py`)

Thin `httpx.AsyncClient` wrapper around the existing FastAPI backend.

```python
BASE = os.environ.get("HAUNTED_AUDIT_API_URL", "http://127.0.0.1:8000")

async def post_run(body: dict) -> dict:          # POST /runs
async def fetch_run(run_id: str) -> dict:        # GET  /runs/{id}
async def wait_for_run(
    run_id: str,
    *,
    poll_interval: float = 2.0,
    timeout: float = 120.0,
) -> dict:
    """Poll until status is complete or error, or timeout."""
```

`post_run` maps the tool's `journey_id` → FastAPI's `variant`/`mode` params. For `journey_id="send-payment"` this is a direct pass-through since the fixture already has `variant` as its discriminator.

`wait_for_run` is used internally by `verify_fix` (which must wait for verification to complete before reporting). `run_journey` itself does NOT wait — it returns immediately with `status: "running"`.

## 7. Fixer (`mcp_server/fixer.py`)

### `propose_fix`

```
propose_fix(run_id) → ProposeFixOutput | ToolError
  │
  ├── fetch_run(run_id)
  │     ├── if status == running  → RUN_IN_PROGRESS
  │     └── if verdict == PASSED  → NO_BARRIER
  ├── extract blocked_element.selector and .tag
  ├── look up source_file via _selector_to_source_file()
  ├── read source_file lines
  ├── _generate_diff(tag, selector, source_lines) → FixDiff
  │     ├── div with no tabindex/role   → replace with <button type="submit">
  │     ├── div with onclick only       → add tabindex="0" role="button"
  │     └── any other case             → add aria-label if accessible_name empty
  └── return ProposeFixOutput (with warning field always set)
```

`_selector_to_source_file()` maps known selectors to source paths:
- `div.pay-btn` → `fixtures/haunted_bank/index.html`
- `button.btn-primary` → `fixtures/haunted_bank/index.html`
- Anything in `dashboard/src/` → resolved from `route_map.py`
- Unknown → `{ "error": "SOURCE_NOT_FOUND" }`

The diff is generated by reading the actual file and computing a unified diff using Python's `difflib.unified_diff`. The AI does not generate the diff; it is computed deterministically from the rule: if `tag == "div"` and the selector contains `pay-btn`, replace the div with a button.

`rationale` in `FixDiff` is a plain-English string that explains the fix in terms a developer can understand. This is the only place where natural-language generation is appropriate (the what-and-why, not the code change itself).

### `verify_fix`

```
verify_fix(run_id, patch) → VerifyFixOutput | ToolError
  │
  ├── locate original source file from run's blocked_element.selector
  ├── copy source file to tmp/verify_{uuid}/
  ├── apply patch via subprocess: patch -p0 < patch_text
  │     └── if patch fails → PATCH_FAILED, rm tmp
  ├── if source is a fixture HTML file:
  │     start Python http.server serving tmp/ on a random port
  ├── run_journey via journey.post_run pointing at tmp/ URL
  ├── wait_for_run until complete
  ├── rm -rf tmp/verify_{uuid}/
  └── return VerifyFixOutput
```

The original file is never touched. The temporary copy path is included in the response so the human can inspect it before it is deleted. Deletion happens in a `finally` block.

## 8. Route Map (`mcp_server/route_map.py`)

Shared between `scanner.py` (for `scan_file`) and the `axe-on-save` hook. Extracted here so the mapping is defined exactly once.

```python
ROUTE_MAP: list[tuple[re.Pattern, list[str]]] = [
    (re.compile(r'TopNav|layout|globals\.css|tailwind\.config', re.I),
     ['/', '#scans', '#journeys', '#fixes', '#kiro', '#reports']),
    (re.compile(r'HeroSection|page\.tsx', re.I), ['/']),
    (re.compile(r'PossessionMode|ChecklistItem|GhostOverlay', re.I), ['/#journeys']),
    (re.compile(r'AgentCard|GhostHuntSection|LiveTimeline', re.I), ['/#scans']),
    (re.compile(r'PipelineSection|CodeBlock|FixPanel|VerifyPanel', re.I), ['/#fixes']),
    (re.compile(r'KiroIntegration|FileTree|HookCode', re.I), ['/#kiro']),
    (re.compile(r'ResultsSection|OutcomeCard|MetricValue', re.I), ['/#reports']),
    (re.compile(r'GhostMascot|GhostSVG', re.I), ['/']),
    (re.compile(r'index\.css|globals\.css', re.I),
     ['/', '/#scans', '/#journeys', '/#fixes', '/#kiro', '/#reports']),
]

def routes_for_file(path: str) -> list[str]:
    basename = Path(path).name
    for pattern, routes in ROUTE_MAP:
        if pattern.search(basename) or pattern.search(path):
            return routes
    return ['/']
```

The `axe-on-save.mjs` script's route map should be refactored to import from this module via a thin JSON export, keeping the two in sync.

## 9. Regression (`mcp_server/regression.py`)

```python
def list_regression_tests(
    workspace_root: Path,
    cache_path: Path | None = None,
) -> ListRegressionTestsOutput:
    """Scan test directories; read cached results; return structured list."""
```

Scanning logic:
1. Glob `agent/tests/test_*.py` for files containing `@pytest.mark.regression` or filenames matching `*send_payment*`.
2. Glob `e2e/*.spec.ts` for files containing `haunted-audit` or `send-payment`.
3. For each found file, check `data/regression_results.json` (written by CI) for the last result.
4. Return `ListRegressionTestsOutput`.

`data/regression_results.json` schema:
```json
{
  "agent/tests/test_scripted_walker.py": {
    "last_result": "PASSED",
    "last_run_at": "2026-11-07T14:22:00Z"
  }
}
```

`regression.py` never runs tests. It reads this file if present; otherwise all `last_result` fields are `null`.

## 10. Severity Classification

Severity classification is deterministic Python code in `scanner.py`, not LLM judgement:

```python
SEVERITY_OVERRIDES: dict[str, str] = {
    # Any violation that prevents form submission = critical
    "keyboard":            "critical",
    "focus-trap":          "critical",
    "button-name":         "serious",   # prevents activation
    "label":               "serious",   # form fields without labels
    "aria-hidden-focus":   "serious",
    "color-contrast":      "moderate",
    "heading-order":       "moderate",
    "duplicate-id-active": "serious",
}

def classify_severity(rule_id: str, axe_impact: str) -> str:
    """Return the effective severity.
    
    axe_impact is the default. SEVERITY_OVERRIDES can promote it.
    Rules are never demoted below their axe default.
    """
    override = SEVERITY_OVERRIDES.get(rule_id)
    if override is None:
        return axe_impact
    # Promotion only: never demote
    order = ["minor", "moderate", "serious", "critical"]
    return order[max(order.index(override), order.index(axe_impact))]
```

The AI writes only the `rationale` field in `FixDiff` and the `failure` field summary. Everything else (verdict, reason_code, impact, WCAG criterion) is deterministic.

## 12. Skill Files

Skills are Markdown files in `.kiro/skills/`. They are activated manually by the user (`#audit-component` in chat) or automatically when Kiro detects the keywords from the skill's description front-matter.

Each skill file structure:
```markdown
---
name: <skill-name>
description: <one line — used for auto-activation matching>
tools:
  - scan_file        # MCP tools this skill uses
  - run_journey
---

# <Skill Name>

## When to use
## Steps
## Output format
## Constraints
```

Skills do not contain code. They describe a workflow for the agent to follow using the MCP tools. The `fix-and-verify` skill explicitly breaks at step 3 and requires human input before calling `verify_fix`.

## 13. Testing Strategy

### Unit tests (`mcp_server/tests/test_*.py`)

Each tool function is tested in isolation. Fixture JSON files in `fixtures/` are loaded as mock responses. No live backend, browser, or network call in unit tests.

| Test file | What it tests |
|---|---|
| `test_scanner.py` | `scan_url` with fixture JSON; error paths (offline, scan-in-progress) |
| `test_journey.py` | `run_journey`, `get_run` with httpx mock; poll timeout path |
| `test_fixer.py` | `propose_fix` diff generation for `div.pay-btn`; `verify_fix` patch-fail path |
| `test_regression.py` | `list_regression_tests` with fixture cache; no-cache path |
| `test_server.py` | Each MCP tool function returns the correct output schema; error inputs return `ToolError` |

### Integration tests (`mcp_server/tests/test_integration.py`)

Marked `@pytest.mark.integration`. Require a live Chromium (from `playwright install chromium`) and the Haunted Bank fixture. Do not require the FastAPI backend for the scan tests; do require it for the journey round-trip test.

Run explicitly:
```bash
pytest -m integration mcp_server/tests/test_integration.py
```

### Test fixtures

`fixtures/scan_url_broken.json` is a real axe-core output captured from `?variant=broken`. It must contain at least one violation with `rule_id` in `{ "aria-roles", "keyboard", "region" }`. It is committed to the repository and used as the mock response in unit tests so tests are deterministic.
