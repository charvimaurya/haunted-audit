# Design: Reference field

- **Bank page.** Add a `.field` after `#amount-slot` with `<label for="reference">Reference</label>` and `<input id="reference" name="reference" type="text" maxlength="60" autocomplete="off">`. It is static HTML, the same in both variants, so no variant-specific barrier is added (REQ-RF-03). `submitPayment` reads `$("reference").value.trim()`, appends ` Reference: <text>.` to the confirmation when non-empty, and clears the field on send and Cancel. `validate` is unchanged.
- **Config.** `JourneyConfig.reference: str = "Electricity bill"`. `build_journey_config` accepts an internal `reference` override (not an API field). The goal sentence adds "and the reference". `build_user_prompt` adds "Reference to enter".
- **Walker.** Add `filled_reference`. After the amount is filled, the next editable field gets `config.reference`. The send condition stays `recipient and amount filled`, so older pages without Reference still pass. The tab budget (`max_steps - 4`) is checked against the new step count in tests.
- **Dashboard.** `DEFAULT_STEPS` and `stepsFromResult` gain "Tab to Reference" (`reached('#reference')`). The Possession demo form gets an empty `pm-reference` input beside Recipient and Amount. Nothing is pre-filled.
- **Evidence.** Re-run `python -m agent.eval.run_eval --runs 5` for scripted, update the table in `docs/evidence.md` from its output, and re-export the seed with `scripts/export_seed.py` from a database that holds those runs.
- **Risks.** (1) Existing tests that count tab stops or steps. (2) Voice runs find fields by accessible name, and Reference is labelled, so they are unaffected; the voice replay phrases are left alone. (3) `docs/evidence-seed.json` is a recorded-fallback input; it is re-exported only from real runs.
